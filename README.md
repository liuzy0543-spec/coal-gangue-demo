# 煤矸石「识别 → 成分预测 → 工艺决策」中期 Demo

大创项目中期汇总用的一体化演示系统：**一张图片进去，得到「逐石物理特征 → 四氧化物预测 → 资源化工艺方案」**。

- 图像识别：复用课题组「煤矸石识别」项目的 YOLOv8s 自训权重（煤块 / 矸石 2 类 + 低置信度规则派生「其他杂石」）
- 成分预测：复用课题组「煤矸石成分」项目的四成分数据与 SiO₂ 交付模型，另在同一 261 行建模表上补训 Al₂O₃ / Fe₂O₃ / CaO
- 知识库：`kb/process_kb.json`（**19 条**煤矸石资源化工艺，按成分区间 + 特征比值 + 物理档位打分）
- 大模型：智谱 GLM-4.5-Flash（免费）或 ZCode / Z.ai Coding Plan，兼容 OpenAI 与 Anthropic 两种协议；**没配 Key 自动走离线知识库，demo 仍可完整跑通**

---

## 1. 快速启动

```bat
cd /d <项目目录>
python app.py
```

浏览器打开 **http://127.0.0.1:7880**

或直接双击 **`一键运行.bat`**：自动启动后端、等待就绪、**优先用 Microsoft Edge** 打开页面（端口已占用时只开页面，不会重复起服务）。

想让演示最快跑起来：点第一步右上角 **「测试集」** 载入案例 A（一张图 + 3 块矸石），第二步会自动生成 **3 组逐石输入**，默认值分别来自库内完整行 **MDL-0327 / MDL-0366 / MDL-0338**；直接点「逐石成分预测」，会弹窗逐石列出四个目标的误差百分比。也可以拖入任意图片，系统按识别到的矸石数量循环使用 `data/demo_samples.json` 中的三条真实行（MDL-0366 / MDL-0338 / MDL-0323）。

首次启动会加载 YOLO（GPU 约 2~5 秒），然后：

1. **第一步**：载入测试集（或拖入图片）→ 看物理特征，必要时点编号旁 **✎** 修正档位
2. **第二步**：按矸石数量自动生成逐石输入卡片，每张卡显示第一步 CV 读到的 D/L/G/T/S；默认值来自库内真实行，可逐石修改
3. **第三步**：点「生成逐石工艺方案」（未配置 API 时自动用离线知识库）

环境：Python 3.10+，依赖见 `requirements.txt`。
CUDA 可用时自动用 GPU，否则 CPU（首图推理约 1~2 秒）。

## 2. 三步流程与页面布局

### 第一步 · 图像识别与物理特征

- 左栏：识别后的标注图 + **图像质量**（清晰度、噪声 σ、光照均匀度、过曝/欠曝、色彩可用性）
- 右栏：**石头编号 → 物理特征** 表
  - 类别：煤块（绿）/ 矸石（红）/ 其他杂石（蓝）
  - 置信度 + **90% 置信区间**（由测试集同类置信度分布估算，见 `models/conf_stats.json`）
  - 五项 CV 特征：`D` 相对粒径、`L` 明度、`G` 光泽高光、`T` 纹理粗糙度、`S` 长宽比
  - 矸石置信度 < 0.70 → 自动归为「其他杂石」，置灰并**不进入后续预测**（规则可调，阈值来自 310 张测试图标定）

特征阈值沿用识别项目《标注准则手册》：取 2263 个标注框实测分位数。鼠标悬停每个特征标签可看口径与实测值。

**物理特征默认可修正**：点编号旁的 ✎，可把 D/L/G/T/S 改成现场判断的档位；保存后表格标「已修正」，并同步更新第二、三步。修正**只影响工艺可行性排序**（大块→骨料/充填、细腻→陶瓷），不改变化学预测——图像本来就不能反演化学成分。弹窗里可一键「恢复 CV 值」。

### 三份测试集（`tests/`）

| 案例 | 图像 | 样品号 | 特点 | 预期路线 |
|---|---|---|---|---|
| A | `case_a.jpg`（5 目标 / 3 矸石） | MDL-0327 + 2 条库内行 | LOI 8.46、SiO₂ 61.5 | 地聚合物 / 水泥 / 陶粒（逐石不同） |
| B | `case_b.jpg`（6 目标 / 4 矸石） | MDL-0323 + 3 条库内行 | LOI 52.58、SiO₂ 20.9（炭质） | 低热值燃料 / CFB 为主 |
| C | `case_c.jpg`（12 目标 / 5 矸石） | MDL-0314 + 4 条库内行 | LOI 12.0、SiO₂ 55.7、粗块多 | 陶粒 / 水泥 / 地聚合物 / 燃料（逐石不同） |

- 载入后自动填逐石六项指标、矿区、来源类型与物料阶段
- 卡片里同时给出**库内实测**四氧化物，方便与预测值对照
- 图像来自识别项目测试集、化验值来自 261 行建模表，**二者是演示配对，不是同一块样品**

### 第二步 · 逐石现场指标 → 成分预测

- **逐石输入卡片**：第一步识别到几块矸石，第二步就生成几组输入（例如 3 块 → S01/S03/S04 三张卡）。卡片头部直接显示第一步 CV 读到的 **D/L/G/T/S** 档位与中文名，证明第二步使用了第一步的结果
- **默认值来自库内真实行**：`data/demo_samples.json` 保存 **MDL-0366 / MDL-0338 / MDL-0323** 三条完整真实行（LOI + 六项指标 + 四目标实测），按矸石顺序填充；测试集案例的第一块优先用案例自带行（MDL-0327/MDL-0323/MDL-0314），其余用三条真实行补齐。三条行来自长治/晋城不同矿区，**演示时统一套用图像矿区**，属于“图像 + 库内行”的演示配对，不是同一批样品
- **逐石独立预测**：每块矸石用自己的输入调用 `/api/predict`，因此中心值可以不同；不再共享同一组化学输入
- **预测误差弹窗**：点「逐石成分预测」后自动弹出每块矸石的 `|预测−真实|/真实×100%`，四个氧化物逐项列出真实值、预测值、绝对误差与误差百分比；点卡片上的「误差」可单石重看
- **低值保护**：真实值 <1 wt% 的目标（如低钙样品的 CaO）仍显示单点误差，但标记「低值*」且不计入 MAPE，避免相对误差被放大后误导
- **矿区**：默认 19 个山西省内煤田/矿区；末尾「＋ 新增矿区…」可填写名称/城市/煤田/煤种/备注，写入 `kb/mining_areas.json`，下次启动仍在
- **矸石来源 / 物料阶段**：参与类别特征编码（洗选矸、掘进矸、原矸等），当前为整图统一设置
- **六项特殊指标**（模型输入，均为马弗炉 + XRF 可测）：LOI 烧失量、K₂O、MgO、Na₂O、TiO₂、SO₃；`_den` 闭合分母 = 六项之和
- **可选进阶（XRD）**：每张卡内可填高岭石、伊利石、石英定量。填了高岭石 → Al₂O₃ 自动切到 **XRD 条件模型（R² 0.587，55/261 覆盖）**；不填 → 回退全表模型（R² 0.272）
- 右侧按 S01/S02… 逐石展示 **SiO₂ / Al₂O₃ / Fe₂O₃ / CaO** 的预测值、90% 区间与 R²，底部指标卡同步切换

> 图像只提供类别与 D/L/G/T/S，**不反演化学成分**；第二步骤的化学默认值来自库内真实行，这是为了让中期 demo 先跑通“逐石 → 逐石误差 → 逐石工艺”的完整链路。真正逐石仍需逐块取样化验，或补「图像特征 ↔ 逐块成分」配对数据。

### 第三步 · 资源化工艺推荐

- 按每块矸石的**预测成分 + 六项指标 + D/L/G/T/S**，从 **19 条知识库**命中候选 → 主推 1 条 + 备选 ≤2 条
- 输出：主导特征（炭质 / 高铝 / 高钙 / 高硅 / 铝硅酸盐 / 低品位）、成分比值（Si/Al、Ca/Si、Fe/Al、LOI/灰分）、**第一步物性档位**、判断依据、机理依据、工艺路线、目标产品、落地风险、参考标准、可信度
- 在线模式：GLM-4.5-Flash 结构化 JSON；离线模式：**成分区间 + 特征比值 + 物性档位**打分
- 左栏「查看知识库」可浏览全部 19 条（成分、比值门控、机理、路线、产品、风险、依据）
- 离线打分规则：
  1. **成分区间**：各氧化物/LOI/SO₃ 是否落在工艺窗口
  2. **特征比值门控**：如高铝提取看 Al/Si、燃料看 LOI/(SiO₂+Al₂O₃)、脱硫看 Ca/Si、石膏看 SO₃/CaO；门控不命中整条降权至 35%
  3. **主导特征匹配**：先按主量成分判定 regime，再对不匹配工艺乘 0.55，避免宽区间“通吃”
  4. **物性小权重**：D3/D4 对陶粒/骨料、T1 对陶瓷/砖的小幅加分（≤0.15），只调排序、不替代化学成分判断
  5. **明确的分化示例**：MDL-0366（Si/Al≈1.9、LOI 17.1）→ 水泥混合材；MDL-0338（Si/Al≈2.2、LOI 13.6、D2）→ 轻质陶粒；MDL-0323（LOI 52.6、LOI/灰分 1.4）→ 低热值燃料；MDL-0327（Si/Al≈2.6、LOI 8.5）→ 地聚合物
- 左栏显示本次上下文（矿区、逐石指标、图像质量）与逐石知识库命中

## 3. 模型与指标（按来源组 5 折 × 3 个分组种子，pooled OOF）

| 目标 | 模型 / 特征 | R²（均值 ± sd） | MAE (wt%) | 样本 / 组 | 说明 |
|---|---|---|---:|---:|---|
| SiO₂ | RidgeCV；LOI + _den + K₂O | **+0.727 ± 0.015** | 4.36 | 261 / 145 | 复用已交付模型，三种子均 > 0.70 |
| Al₂O₃（全表） | RidgeCV；LOI + _den + K₂O + 高岭石 | +0.272 ± 0.013 | 5.15 | 261 / 145 | 未填 XRD 高岭石时的回退模型 |
| **Al₂O₃（XRD 条件）** | RidgeCV；高岭石 + LOI + 矿物学上界 | **+0.587 ± 0.018** | 4.24 | **55 / 14** | 仅当填了高岭石时启用，覆盖 55/261 |
| Fe₂O₃ | XGBoost；LOI + _den + K₂O + 高岭石 + 伊利石 + 石英 + Na₂O | +0.338 ± 0.008 | 2.76 | 261 / 145 | 比原 Ridge 版 +0.020 |
| CaO | XGBoost；MgO + SO₃ + TiO₂ | +0.120 ± 0.037 | 2.02 | 261 / 145 | 仍弱，但比原 Ridge 版 +0.072 |

模型：RidgeCV / XGBoost + 中位数插补（含缺失指示）+ 标准化（Ridge）+ OneHot(省/市/来源/阶段)。
数据：`data/成分建模数据_261.xlsx`（课题组整理的 261 行建模表，含 30 列，四目标同表）。

> 完整的“改前→改后、0.5+ 的来源、试过但没采用的方案”见 **[指标复核报告.md](指标复核报告.md)**。

### 3.1 关于「Al₂O₃ 曾经到 0.5+」的核实

确实到过，而且现在可以复现：

- 课题组「第 16 轮数据检索与模型优化」报告记录 **Al₂O₃ +0.5558**（n=72 / 18 组），条件是 **只取有 XRD 高岭石定量的样品**，特征为高岭石，模型 RidgeCV，并加矿物学上界 `Al₂O₃ ≤ (高岭石×0.395 + 伊利石×0.30)×1.8 + 8`。
- 本 demo 在 261 行表上按同一配方复现：**+0.5872 ± 0.0183（n=55 / 14 组，MAE 4.24）**。55 条与 72 条的差异来自本表只保留了 55 条带高岭石定量的样品。
- **不能把这个数字当成“全表 261 条”的成绩**：全表只有 55 条有高岭石，其余靠中位数插补，所以全表模型仍是 +0.272。页面上只要填了高岭石，Al₂O₃ 会自动切到条件模型并打上 `XRD 条件 R² 0.59` 标记；不填则回退 +0.272 并如实显示。
- 这正是“缺的是矿物相定量、不是样本量”的实证：Al₂O₃ 与高岭石的相关系数在本表达 **0.818**，但覆盖只有 21%。

> 诚实说明：CaO 仍接近随机（+0.120），Al₂O₃ 全表模型偏弱；页面上直接展示 R² 与 MAE，工艺推荐也标注可信度。新增的 Fe/Ca 模型与 XRD 条件模型都可在 `scripts/train_models.py` 一键复训。

复训：

```bat
python scripts\train_models.py
```

## 6. 扩展方式

### 加矿区
页面「＋ 新增矿区」即可，字段：名称、省份、城市、所属煤田、煤种、备注。写入 `kb/mining_areas.json`。

### 加工艺
在 `kb/process_kb.json` 的 `entries` 追加一条，字段见 `kb/README.md`：

```json
{
  "id": "new_process",
  "name": "工艺名",
  "category": "建材/化工/环保/能源/生态",
  "conditions": {"SiO2": [40, 70], "Al2O3": [15, 35], "Fe2O3": [0, 10], "CaO": [0, 10], "LOI": [0, 30]},
  "ratios": {"SI_AL": [1.6, 3.4], "CA_SI": [0, 0.2]},
  "gate": ["SI_AL", "LOI"],
  "regime": ["aluminosilicate", "high_si"],
  "physical": {"D3": 0.04, "T2": 0.02},
  "process": "工艺路线",
  "products": "产品",
  "basis": "成分/比值与工艺窗口的机理依据",
  "risk": "风险",
  "ref": "标准/文献/案例依据"
}
```

> `gate` 是定义性比值门控（如燃料 `LOI_ASH`、高铝 `AL_SI`），任一不命中降权至 35%；`regime` 是主导特征白名单，不匹配乘 0.55；`physical` 按 D/L/G/T/S 档位加小分（总上限 0.15）。旧字段 `reason` 已由 `basis` 替代，新增后刷新页面即可在「查看知识库」里看到。

离线打分流程：

1. **成分区间**：`conditions` 中各氧化物/LOI/SO₃ 是否落入窗口
2. **比值门控**：`ratios` 与 `gate`，避免用宽区间“蹭分”
3. **主导特征**：`dominant_regime()` 先判定炭质/高铝/高铁/高钙/高硅/铝硅酸盐/低品位，再做匹配修正
4. **物性偏好**：第一步 D/L/G/T/S 档位只做 ≤0.15 的排序加分
5. **结果**：主推 1 条 + 备选 ≤2 条，并给出比值、机理、路线、产品、风险、标准

在线模式会把知识库整体塞进 prompt，并把每块矸石的成分、比值、主导特征、物性一起传入，要求模型只从中选择。

### 换模型 / 加目标
- 在 `scripts/train_models.py` 的 `FEATURES` 加目标与特征，重训后 `models/metrics.json` 自动更新
- 改 `INPUT_SCHEMA` 可增删前端输入框（前端按 `input_schema.json` 自动渲染）

## 7. 已知局限（答辩时建议主动说明）

1. **逐石成分的“逐石”是输入逐石，不是图像反演**：化学默认值来自库内真实行，逐石输入可以让中心值不同，但图像本身只提供类别与 D/L/G/T/S；真正逐石仍需逐块取样化验，或补齐「图像特征 → 成分」的配对训练集（目前无此数据）。
2. **Al₂O₃ / CaO 预测弱**（Al₂O₃ 全表 R² 0.272、XRD 条件 0.587；CaO 0.120）：缺伊利石、方解石、白云石、黄铁矿定量；第 19 轮已给出补齐路径。
3. **误差百分比对低值敏感**：真实 CaO 0.28 wt% 时 0.9 wt% 的绝对误差就是 318%，页面用「低值*」排除出 MAPE，但仍会显示单点误差。
4. **图像‑化学无因果**：项目《理化性质评估报告》已实证普通可见光图像不能反演化学成分，本 demo 未越界使用。
5. **知识库阈值是工程经验区间**，不是标准强制值；落地必须小试/中试 + 重金属/放射性/安定性检测。
6. **识别模型只训了煤块/矸石两类**，「其他杂石」是低置信度规则派生，不是独立类别。

## 8. 故障排查

| 现象 | 处理 |
|---|---|
| 页面能开但识别报错 | 确认 `models/yolo_coal_gangue.pt` 存在；看启动日志 `[WARN] YOLO` |

| 预测全是中位数 | 六项指标没填；至少填 LOI，其余按中位数插补（页面有提示） |
| 第三步一直离线 | 未配置 Key 或 Key 失效；点「测试连通」看错误 |
| 端口占用 | `python app.py --port 7881` |
| 上传大图失败 | 限制 32 MB，先压缩 |
