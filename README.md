# 煤矸石「识别 → 成分预测 → 工艺决策」中期 Demo

大创项目中期汇总用的一体化演示系统：**一张图片进去，得到「逐石物理特征 → 四氧化物预测 → 资源化工艺方案」**。

- 图像识别：复用课题组「煤矸石识别」项目的 YOLOv8s 自训权重（煤块 / 矸石 2 类 + 低置信度规则派生「其他杂石」）
- 成分预测：复用课题组「煤矸石成分」项目的四成分数据与 SiO₂ 交付模型，另在同一 261 行建模表上补训 Al₂O₃ / Fe₂O₃ / CaO
- 知识库：`kb/process_kb.json`（**16 条**煤矸石资源化工艺，含实测案例区间与扩展说明）
- 大模型：智谱 GLM-4.5-Flash（免费）或 ZCode / Z.ai Coding Plan，兼容 OpenAI 与 Anthropic 两种协议；**没配 Key 自动走离线知识库，demo 仍可完整跑通**

---

## 1. 快速启动

```bat
cd /d <项目目录>
python app.py
```

浏览器打开 **http://127.0.0.1:7880**

或直接双击 **`一键运行.bat`**：自动启动后端、等待就绪、**优先用 Microsoft Edge** 打开页面（端口已占用时只开页面，不会重复起服务）。

想让演示最快跑起来，可以直接在第二步点「开始成分预测」：默认已载入数据库完整示例 **MDL-0366（山西长治，LOI 17.11 + 四种氧化物实测）**，预测后会弹窗给出四个目标的误差百分比。也可以点第一步右上角 **「测试集」**，三份案例都是「一张图 + 一组含 LOI 的库内实测数据」，载入后指标自动填好。

首次启动会加载 YOLO（GPU 约 2~5 秒），然后：

1. **第一步**：载入测试集（或拖入图片）→ 看物理特征，必要时点编号旁 **✎** 修正档位
2. **第二步**：默认示例已填好六项指标；可直接预测看误差，也可改值后重新预测
3. **第三步**：点「生成逐石工艺方案」（未配置 API 时自动用离线知识库）

环境：Python 3.10+，依赖见 `requirements.txt`。
CUDA 可用时自动用 GPU，否则 CPU（首图推理约 1~2 秒）。

## 2. 三步流程与页面布局

### 第一步 · 图像识别与物理特征

- 左栏：识别后的标注图 + **图像质量**（清晰度、噪声 σ、光照均匀度、过曝/欠曝、色彩可用性）
- 右栏：**石头编号 → 物理特征** 表
  - 类别：煤块（绿）/ 矸石（红）/ 其他杂石（蓝）
  - 置信度 + **90% 置信区间**（由测试集同类置信度分布估算，见 `models/conf_stats.json`）
  - 五项 CV 特征：`D` 相对粒径、`L` 明度、`G` 光泽高光、`T` 纹理粗糙度、`S` 长宽比
  - 矸石置信度 < 0.70 → 自动归为「其他杂石」，置灰并**不进入后续预测**（规则可调，阈值来自 310 张测试图标定）

特征阈值沿用识别项目《标注准则手册》：取 2263 个标注框实测分位数。鼠标悬停每个特征标签可看口径与实测值。

**物理特征默认可修正**：点编号旁的 ✎，可把 D/L/G/T/S 改成现场判断的档位；保存后表格标「已修正」，并同步更新第二、三步。修正**只影响工艺可行性排序**（大块→骨料/充填、细腻→陶瓷），不改变化学预测——图像本来就不能反演化学成分。弹窗里可一键「恢复 CV 值」。

### 三份测试集（`tests/`）

| 案例 | 图像 | 样品号 | 特点 | 预期路线 |
|---|---|---|---|---|
| A | `case_a.jpg`（5 目标 / 3 矸石） | MDL-0327 | LOI 8.46、SiO₂ 61.5 | 水泥混合材 / 烧结砖 / 骨料 |
| B | `case_b.jpg`（6 目标 / 4 矸石） | MDL-0323 | LOI 52.58、SiO₂ 20.9（炭质） | 低热值燃料 / CFB |
| C | `case_c.jpg`（12 目标 / 5 矸石） | MDL-0314 | LOI 12.0、SiO₂ 55.7、粗块多 | 水泥 / 骨料（逐块 D 不同） |

- 载入后自动填六项指标、矿区、来源类型与物料阶段
- 卡片里同时给出**库内实测**四氧化物，方便与预测值对照
- 图像来自识别项目测试集、化验值来自 261 行建模表，**二者是演示配对，不是同一块样品**

### 第二步 · 矿区信息与现场指标 → 成分预测

- **默认示例（数据库真实行）**：页面载入 **MDL-0366（山西长治 · 潞安矿区）**，六项指标 + LOI + 四种氧化物实测齐全，来源是晋平煤业公开环评的矸石分析结果。数值可直接改，改完重新预测即可
- **预测误差弹窗**：点「开始成分预测」后自动弹出四个目标的 `|预测−真实|/真实×100%`，同时列出真实值、预测值、绝对误差与 MAPE；点「预测误差」可随时重开
- **矿区**：默认 19 个山西省内煤田/矿区；末尾「＋ 新增矿区…」可填写名称/城市/煤田/煤种/备注，写入 `kb/mining_areas.json`，下次启动仍在
- **矸石来源 / 物料阶段**：参与类别特征编码（洗选矸、掘进矸、原矸等）
- **六项特殊指标**（模型输入，均为马弗炉 + XRF 可测）：LOI 烧失量、K₂O、MgO、Na₂O、TiO₂、SO₃；`_den` 闭合分母 = 六项之和
- **可选进阶（XRD）**：高岭石、伊利石、石英定量。填了高岭石 → Al₂O₃ 自动切到 **XRD 条件模型（R² 0.587，55/261 覆盖）**；不填 → 回退全表模型（R² 0.272）。伊利石收紧矿物学上界，石英进入 Fe₂O₃ 模型
- 右侧表格会按情况打 `XRD 条件 R² 0.59` 标记，底部指标卡同步切换，避免把条件模型成绩误读成全表成绩
- 右栏：**石头编号 → SiO₂ / Al₂O₃ / Fe₂O₃ / CaO**，每格给出预测值、区间（模型 RMSE × 图像可信系数）与条形图

> 同一张图里的矸石共享同一批次成分输入，所以中心值相同；**逐石差异体现在置信区间宽度**（检测置信度 + 图像清晰度）。图像只用于识别与物理特征，**不用于反演化学成分** —— 这是项目前 19 轮的实证结论。

### 第三步 · 资源化工艺推荐

- 按每块矸石的成分 + 物理特征，从 **16 条知识库**命中候选 → 主推 1 条 + 备选 ≤2 条
- 输出：判断依据（引用具体成分数值）、工艺路线、目标产品、落地风险、参考依据、可信度
- 在线模式：GLM-4.5-Flash 结构化 JSON；离线模式：知识库区间打分 + 粒径/纹理可行性加权
- 左栏「查看知识库」可浏览全部 16 条（条件、路线、产品、风险、依据），新增条目即时生效
- 离线打分的三条工程修正：**首条件门控**（如高铝提取看 Al₂O₃、脱硫看 CaO，首条件不命中降权 65%）、**高 LOI 修正**（>20% 时水泥 −0.12、燃料 +0.08）、**物理可行性加权**（D4/D3→骨料，D1/D2→水泥，T1→陶瓷）
- 左栏显示本次上下文（矿区、指标、图像质量）与逐石知识库命中

## 3. 模型与指标（按来源组 5 折 × 3 个分组种子，pooled OOF）

| 目标 | 模型 / 特征 | R²（均值 ± sd） | MAE (wt%) | 样本 / 组 | 说明 |
|---|---|---|---:|---:|---|
| SiO₂ | RidgeCV；LOI + _den + K₂O | **+0.727 ± 0.015** | 4.36 | 261 / 145 | 复用已交付模型，三种子均 > 0.70 |
| Al₂O₃（全表） | RidgeCV；LOI + _den + K₂O + 高岭石 | +0.272 ± 0.013 | 5.15 | 261 / 145 | 未填 XRD 高岭石时的回退模型 |
| **Al₂O₃（XRD 条件）** | RidgeCV；高岭石 + LOI + 矿物学上界 | **+0.587 ± 0.018** | 4.24 | **55 / 14** | 仅当填了高岭石时启用，覆盖 55/261 |
| Fe₂O₃ | XGBoost；LOI + _den + K₂O + 高岭石 + 伊利石 + 石英 + Na₂O | +0.338 ± 0.008 | 2.76 | 261 / 145 | 比原 Ridge 版 +0.020 |
| CaO | XGBoost；MgO + SO₃ + TiO₂ | +0.120 ± 0.037 | 2.02 | 261 / 145 | 仍弱，但比原 Ridge 版 +0.072 |

模型：RidgeCV / XGBoost + 中位数插补（含缺失指示）+ 标准化（Ridge）+ OneHot(省/市/来源/阶段)。
数据：`data/成分建模数据_261.xlsx`（课题组整理的 261 行建模表，含 30 列，四目标同表）。

> 完整的“改前→改后、0.5+ 的来源、试过但没采用的方案”见 **[指标复核报告.md](指标复核报告.md)**。

### 3.1 关于「Al₂O₃ 曾经到 0.5+」的核实

确实到过，而且现在可以复现：

- 课题组「第 16 轮数据检索与模型优化」报告记录 **Al₂O₃ +0.5558**（n=72 / 18 组），条件是 **只取有 XRD 高岭石定量的样品**，特征为高岭石，模型 RidgeCV，并加矿物学上界 `Al₂O₃ ≤ (高岭石×0.395 + 伊利石×0.30)×1.8 + 8`。
- 本 demo 在 261 行表上按同一配方复现：**+0.5872 ± 0.0183（n=55 / 14 组，MAE 4.24）**。55 条与 72 条的差异来自本表只保留了 55 条带高岭石定量的样品。
- **不能把这个数字当成“全表 261 条”的成绩**：全表只有 55 条有高岭石，其余靠中位数插补，所以全表模型仍是 +0.272。页面上只要填了高岭石，Al₂O₃ 会自动切到条件模型并打上 `XRD 条件 R² 0.59` 标记；不填则回退 +0.272 并如实显示。
- 这正是“缺的是矿物相定量、不是样本量”的实证：Al₂O₃ 与高岭石的相关系数在本表达 **0.818**，但覆盖只有 21%。

> 诚实说明：CaO 仍接近随机（+0.120），Al₂O₃ 全表模型偏弱；页面上直接展示 R² 与 MAE，工艺推荐也标注可信度。新增的 Fe/Ca 模型与 XRD 条件模型都可在 `scripts/train_models.py` 一键复训。

复训：

```bat
python scripts\train_models.py
```

## 4. 大模型 API 配置（GLM-4.5-Flash）

页面右上角「⚙ API 设置」：

| 预设 | Base URL | 协议 / 说明 |
|---|---|---|
| 智谱 BigModel · 通用 | `https://open.bigmodel.cn/api/paas/v4` | OpenAI；**默认**，免费 `glm-4.5-flash` 走这里 |

| Z.ai · Coding（OpenAI） | `https://api.z.ai/api/coding/paas/v4` | OpenAI；zcode 海外 |
| Z.ai · Coding（Anthropic） | `https://api.z.ai/api/anthropic` | Anthropic |
| ZCode 编程套餐 | `https://zcode.z.ai/api/v1/zcode-plan/anthropic` | Anthropic；默认模型 `GLM-5.3-Flash` |

模型名默认 `glm-4.5-flash`。ZCode 的 API Key 分「编程套餐 Key」和「开放平台 Key」两类：**免费 glm-4.5-flash 必须走通用端点**（`/api/paas/v4`）；如果用的是 Coding Plan 套餐 Key，请切到 Coding 端点并把协议改成 Anthropic，否则会 401 或无额度。

- Key 只写入本机 `config.json`（已 gitignore），也可用环境变量 `GLM_API_KEY` / `ZHIPU_API_KEY`
- 「测试连通」会发一条最小请求，显示延迟
- 接口失败 / 超时 / 返回非 JSON 时，自动回退离线知识库，并在结果上方显示回退原因
- 免费模型额度与命名以智谱控制台为准；若 `glm-4.5-flash` 下线，改模型名即可（如 `glm-4.7-flash`）

## 6. 扩展方式

### 加矿区
页面「＋ 新增矿区」即可，字段：名称、省份、城市、所属煤田、煤种、备注。写入 `kb/mining_areas.json`。

### 加工艺
在 `kb/process_kb.json` 的 `entries` 追加一条，字段见 `kb/README.md`：

```json
{
  "id": "new_process",
  "name": "工艺名",
  "category": "建材/化工/环保/能源/生态",
  "conditions": {"SiO2": [40, 70], "Al2O3": [15, 35], "Fe2O3": [0, 10], "CaO": [0, 10], "LOI": [0, 30]},
  "process": "工艺路线",
  "products": "产品",
  "reason": "一般性理由",
  "risk": "风险",
  "ref": "依据"
}
```

> `conditions` 的**第一个键必须是该工艺的定义性指标**（如高铝提取 Al₂O₃、脱硫 CaO、燃料 LOI），否则会被门控降权。新增后刷新页面即可在「查看知识库」里看到。

离线打分按区间命中率计算，并做三条工程修正：

1. **首条件门控**：每条工艺的第一个指标视为定义性指标（高铝提取看 Al₂O₃、脱硫看 CaO、燃料看 LOI……），不命中则整条降权至 35%，避免靠 Fe/Ca 宽区间“蹭分”
2. **高 LOI 惩罚**：LOI > 20% 时水泥/烧结砖 −0.12，低热值燃料 +0.08（高烧失量物料做建材需额外配料）
3. **物理可行性加权**：D4 骨料 +0.12、D3 +0.08；D1/D2 水泥 +0.04；T1 陶瓷 +0.05。物理特征**只调排序，不推断成分**

在线模式会把知识库整体塞进 prompt，要求模型只从中选择。

### 换模型 / 加目标
- 在 `scripts/train_models.py` 的 `FEATURES` 加目标与特征，重训后 `models/metrics.json` 自动更新
- 改 `INPUT_SCHEMA` 可增删前端输入框（前端按 `input_schema.json` 自动渲染）

## 7. 已知局限（答辩时建议主动说明）

1. **逐石成分不是独立预测**：化学输入是批次级；逐石只体现在图像特征与置信区间。真正逐石需要逐块取样化验，或补齐「图像特征 → 成分」的配对训练集（目前无此数据）。
2. **Al₂O₃ / CaO 预测弱**（Al₂O₃ 全表 R² 0.272、XRD 条件 0.587；CaO 0.120）：缺伊利石、方解石、白云石、黄铁矿定量；第 19 轮已给出补齐路径。
3. **图像‑化学无因果**：项目《理化性质评估报告》已实证普通可见光图像不能反演化学成分，本 demo 未越界使用。
4. **知识库阈值是工程经验区间**，不是标准强制值；落地必须小试/中试 + 重金属/放射性/安定性检测。
5. **识别模型只训了煤块/矸石两类**，「其他杂石」是低置信度规则派生，不是独立类别。

## 8. 故障排查

| 现象 | 处理 |
|---|---|
| 页面能开但识别报错 | 确认 `models/yolo_coal_gangue.pt` 存在；看启动日志 `[WARN] YOLO` |
| 首图很慢 | 首次加载权重 + CUDA 初始化；后续约 0.1~0.5 s/张 |
| 预测全是中位数 | 六项指标没填；至少填 LOI，其余按中位数插补（页面有提示） |
| 第三步一直离线 | 未配置 Key 或 Key 失效；点「测试连通」看错误 |
| 端口占用 | `python app.py --port 7881` |
| 上传大图失败 | 限制 32 MB，先压缩 |
